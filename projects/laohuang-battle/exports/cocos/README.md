# cocos Export · laohuang-battle

This is a **Cocos Creator** handoff package, not a runnable Cocos project.
`native_project_files: false` — provides deterministic JSON manifests only; `.prefab` / `.scene` / atlas auto-importers are outside the built-in export scope.

> Agent goal: read the JSON in this directory and **automatically apply** the generated UI to the target Cocos project.

## Contents

| File | Purpose |
|---|---|

Relative path convention: `texture` points to `assets/atlases/…` under the project root.

## Agent Quickstart (Read Me → Run It)

Goal: after this section, the Agent can drop the demo into a Cocos Creator 3.x project and get a clickable 7-screen skeleton without asking questions or editing generated files.
Real business logic is out of scope here (all demo events only log `[kui-demo]`); once it runs, follow "Automatic Integration Steps" to wire up a real project.

1. **Copy files**: the two `.ts` files under `demo/` → `assets/kui-demo/`;
   Atlas PNG → `assets/resources/ui-main.png` (if missing, the demo falls back to a placeholder panel and logs).
2. **Create a scene**: new scene (with Canvas, recommended design resolution 1080×1920 portrait) → create an empty node under Canvas
   → add the `KuiDemoBuilder` component → save.
3. **Run**: **Preview (Browser)** in the editor toolbar.
4. **Verification**: the browser Console shows `[kui-demo] event=boot screens=7`; the bottom nav switches
   7 screens, and each tap/switch logs one `[kui-demo]` line (format in `demo/README.md`).
5.
1. **Next**: use `ui-main.json` as the single source of truth for the real project, and mirror the demo's assembly approach against the "Mapping Reference" below.

(`ui-main.json`)

| Field | Meaning |
|---|---|
| `schema_version` | Manifest version, currently `1` |
| `engine` | `cocos` |
| `atlas_id` / `atlas_size` | Atlas ID and pixel size `[w, h]` |
| `texture` | Atlas image path |
| `frames.<sprite>.rect` | `{x, y, width, height}`, atlas pixel rectangle |
| `frames.<sprite>.offset` | `{x, y}`, offset from center (always 0 on export) |
| `frames.<sprite>.originalSize` | `{width, height}`, original size |
| `frames.<sprite>.capInsets` | `[left, right, top, bottom]`, 9-slice insets (px) |

`capInsets` all `0` uses a normal Sprite; non-zero uses the **Sliced** type.

## Two-State (normal / pressed)

Clickable controls must provide both `default` and `pressed` states (same `component_id`, different `state` entries):
Bind them as the control's normal / pressed skins on the engine side. For clickable controls missing a pressed entry in the atlas, go back to the component breakdown stage
to fill it in before export; when the demo lacks it, fall back to a darkened normal state (≈14%) so the two states remain distinguishable.

## Automatic Integration Steps (Agent)

1. **Import the atlas**  
   Copy `texture` into the Cocos project's `assets/` (recommended: `assets/ui/atlases/`).  
   If the project uses Auto Atlas / Texture Packer, generate SpriteFrames by name instead; otherwise use this JSON to build Frames manually.

2. **Create SpriteFrames one by one** (iterate `frames`)  
   - `rect` ← atlas crop rectangle  
   - `originalSize` ← original size  
   - `offset` ← offset (0)  
   - `capInsets` → the frame's nine-patch / inset field (version differences: `Insets` / `Sliced` border)  
   Keep names identical to the key (including the `state` suffix) for easy button state switching.

3. **Bind UI nodes**  
   - Background → `Sprite` + `UITransform`, full stretch.  
   - Button → `Button`, `SpriteFrame` switches by `state` (normal/pressed/disabled); use **Sliced** + `capInsets` for stretchable base images.  
   - Icon → `Sprite`, keep the `originalSize` ratio.  
   - Progress bar → `ProgressBar` or a two-layer Sprite mask.  
   - `text_policy = no-text`: the image is text-free; overlay a `Label`.

4. **Theme** (optional)  
   Colors / corner radius / font sizes: see `contracts/style-contract.yaml` or `exports/web/tokens.css`; build a Prefab theme component or a constants table.

5. **Self-check**  
   - Sliced Sprites keep corners undistorted after stretching, with a tileable center.  
   - `rect` falls fully inside the atlas and matches `originalSize`.  
   - Never claim to have generated `.prefab` / `.scene` / atlas auto-import results.

## Mapping Reference

| kui field | Cocos |
|---|---|
| `texture` | `Texture2D` / atlas |
| `frames.*.rect` | `SpriteFrame.rect` |
| `frames.*.originalSize` | `SpriteFrame.originalSize` |
| `frames.*.capInsets` | Sliced border / `Insets` |
| `frames.*.offset` | `SpriteFrame.offset` |
| `component_id` / `state` | Node naming / Button state graphics |

## Reference Demo (demo/)

`demo/` is a **runnable reference implementation** shipped with the exporter: the fixed-template assembler reads `ui-data.ts`
(an engine-language mirror of `ui-main.json`) and assembles each screen into a node tree by layout regions,
with every event and screen switch printing one `[kui-demo]` line. Use cases:

- **Smoke test**: run it once to check whether the handoff JSON is self-consistent (region/margins/screen structure);
- **Reference implementation**: when integrating a real project, mirror the demo's assembly approach to reduce guesswork.

See `demo/README.md` for details and verification steps.

## Boundaries

- Does not generate `.prefab` / `.scene` / `.meta` / script components.
- Does not write to project `settings` or bind physics/networking.
- Business logic and asset-loading strategy are wired up by the game project itself.
