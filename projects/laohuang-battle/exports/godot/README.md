# godot Export · laohuang-battle

This is a **Godot** handoff package, not a runnable Godot project.
`native_project_files: false` — provides deterministic JSON manifests only; native `.tscn` / `.tres` / `.import` files are outside the built-in export scope.

> Agent goal: read the JSON in this directory and **automatically apply** the generated UI to the target Godot project.

## Agent Quickstart (Read Me → Run It)

Goal: after this section, the Agent can drop the demo into a Godot 4 project and get a clickable 7-screen skeleton without asking questions or editing generated files.
Real business logic is out of scope here (all demo events only log `[kui-demo]`); once it runs, follow "Automatic Integration Steps" to wire up a real project.

1. **Project**: any Godot 4.x project (a new empty one is fine).
2. **Copy files**: the whole `demo/` directory → `res://demo/`; Atlas PNG → `res://assets/atlases/ui-main.png` (if missing, the demo falls back to a placeholder panel and logs).
3. **Create a scene**: new scene, root node = **Control**, attach `res://demo/main.gd`, press F6 to run the current scene.
4. **Verification**: the Output panel shows `[kui-demo] event=boot screens=7`; the bottom nav switches 7 screens, and each tap/switch logs one `[kui-demo]` line (format in `demo/README.md`).
5. **Next**: use `ui-main.json` as the single source of truth for the real project, and mirror the demo's assembly approach against the "Mapping Reference" below.

## Field Semantics (`ui-main.json`)

| Field | Meaning |
|---|---|
| `schema_version` | Manifest version, currently `1` |
| `engine` | `godot` |
| `atlas_id` / `atlas_size` | Atlas ID and pixel size `[w, h]` |
| `texture` | Atlas image path (PNG/SVG source) |
| `resources.<sprite>.texture` | Same as above (redundant, for easy single-item reference) |
| `resources.<sprite>.region` | `[x, y, w, h]`, atlas pixel rectangle (origin top-left) |
| `resources.<sprite>.patch_margins` | `[left, right, top, bottom]`, 9-patch margins (px) |
| `resources.<sprite>.component_id` | Semantic component ID |
| `resources.<sprite>.state` | State (`default` / `pressed` / …) |

`patch_margins` all `0` means stretch the whole image or no edge slicing; non-zero uses NinePatch.

## Two-State (normal / pressed)

Clickable controls must provide both `default` and `pressed` states (same `component_id`, different `state` entries):
On the Godot side, bind them as the Button / TextureButton normal / pressed skins (the demo shows this with StyleBoxTexture).
For clickable controls missing a pressed entry in the atlas, go back to the component breakdown stage to fill it in before export; when the demo lacks it, fall back to a darkened normal skin.

## Automatic Integration Steps (Agent)

1. **Copy the atlas**  
   Copy the image at `texture` into the Godot project, recommended `res://assets/atlases/`, keeping the filename.

2. **Create Sprite resources one by one** (iterate `resources`)  
   - Fixed size (icons, decorations): `AtlasTexture`, `atlas = texture`, `region = Rect2(x, y, w, h)`.  
   - Stretchable skins (`patch_margins` not all 0): `NinePatchRect` or `StyleBoxTexture`:  
     - `texture` = the AtlasTexture above  
     - `patch_margin_left/right/top/bottom` ← the matching `patch_margins` values  
   - Progress bar: `TextureProgressBar` + nine-patch background/fill.

3. **Place nodes by component semantics**  
   - Background → `TextureRect` / `NinePatchRect`, full-screen anchors.  
   - Button → `Button` or `TextureButton`; normal/pressed/disabled use regions of different `state` under the same `component_id`.  
   - Icon → `TextureRect` + AtlasTexture.  
   - If `text_policy = no-text`: the image has no text; overlay a `Label`; do not write text onto the texture in the engine.

4. **Theme colors** (optional)  
   Colors / corner radius / font sizes: see `contracts/style-contract.yaml` or `exports/web/tokens.css`; build a Godot `Theme` and bind via `theme_override_*`.

5. **Self-check**  
   - 9-slice keeps corners undistorted after stretching, with a tileable center.  
   - `region` matches the source PNG pixels with no cropping.  
   - Never claim to have generated `.tscn` / `.tres` / a SpriteAtlas importer.

## Mapping Reference

| kui field | Godot |
|---|---|
| `region` | `AtlasTexture.region` / `Sprite2D.region_rect` |
| `patch_margins` | `NinePatchRect.patch_margin_*` / `StyleBoxTexture.region_rect` |
| `9-slice` | `NinePatchRect` or `StyleBoxTexture` |
| `component_id` | Node naming / scene component script |
| `state` | `BaseButton` state texture |

## Reference Demo (demo/)

`demo/` is a **runnable reference implementation** shipped with the exporter: `main.gd` (fixed template) reads `ui_data.gd`
(a GDScript mirror of `ui-main.json`) and assembles each screen into a node tree by layout regions,
with every Button event and screen switch printing one `[kui-demo]` line. Use cases:

- **Smoke test**: run it once to check whether the handoff JSON is self-consistent (region/margins/screen structure);
- **Reference implementation**: when integrating a real project, mirror the demo's assembly approach to reduce guesswork.

See `demo/README.md` for details and verification steps.

## Boundaries

- Does not generate `.tscn` / `.tres` / `.import` / Autoload.
- Does not modify Project Settings, input maps, or the render pipeline.
- Business logic, signals, and saves are wired up by the game project itself.
