# unity Export · laohuang-battle

This is a **Unity** handoff package, not a runnable Unity project.
`native_project_files: false` — provides deterministic JSON manifests only; `.meta` / SpriteAtlas / Prefab are outside the built-in export scope.

> Agent goal: read the JSON in this directory and **automatically apply** the generated UI to the target Unity project.

## Agent Quickstart (Read Me → Run It)

Goal: after this section, the Agent can drop the demo into a Unity project and get a clickable 7-screen skeleton without asking questions or editing generated files.
Real business logic is out of scope here (all demo events only log `[kui-demo]`); once it runs, follow "Automatic Integration Steps" to wire up a real project.

1. **Copy files**: the two `.cs` files under `demo/` → `Assets/KuiDemo/` (any directory name works);
   Atlas PNG → `Assets/Resources/UI/Atlases/ui-main.png` (if missing, the demo falls back to a placeholder panel and logs).
2. **Run**: just press **Play** — `RuntimeInitializeOnLoadMethod` auto-creates the Canvas + EventSystem, with zero scene setup.
3. **Verification**: the Console shows `[kui-demo] event=boot screens=7`; the bottom nav switches
   7 screens, and each tap/switch logs one `[kui-demo]` line (format in `demo/README.md`).
4.
1. **Next**: use `ui-main.json` as the single source of truth for the real project, and mirror the demo's assembly approach against the "Mapping Reference" below.

(`ui-main.json`)

| Field | Meaning |
|---|---|
| `schema_version` | Manifest version, currently `1` |
| `engine` | `unity` |
| `atlas_id` / `atlas_size` | Atlas ID and pixel size `[w, h]` |
| `texture` | Atlas image path |
| `spriteMode` | Fixed `"Multiple"` |
| `sprites[].name` | Sprite name (semantic name, with state suffix) |
| `sprites[].rect` | `[x, y, w, h]`, texture pixel rectangle |
| `sprites[].pivot` | `[px, py]`, 0–1 normalized pivot (default `[0.5, 0.5]`) |
| `sprites[].border` | `[left, right, top, bottom]`, Sliced 9-patch border (px) |
| `sprites[].pixelsPerUnit` | Fixed `100` |

`border` all `0` uses Simple/Full; non-zero uses **Sliced**.

## Two-State (normal / pressed)

Clickable controls must provide both `default` and `pressed` states (same `component_id`, different `state` entries):
Bind them as the control's normal / pressed skins on the engine side. For clickable controls missing a pressed entry in the atlas, go back to the component breakdown stage
to fill it in before export; when the demo lacks it, fall back to a darkened normal state (≈14%) so the two states remain distinguishable.

## Automatic Integration Steps (Agent)

1. **Import the atlas**  
   Copy `texture` into the Unity project (recommended: `Assets/UI/Atlases/`).  
   TextureImporter: `Texture Type = Sprite (2D and UI)`, `Sprite Mode = Multiple`, `Pixels Per Unit = 100`, Filter/Compression per project standards (UI usually Point/Bilinear + None).

2. **Write Sprite sub-assets** (iterate `sprites[]`)  
   For each entry create a SpriteMetaData (or equivalent Sprite asset):  
   - `name` ← `name`  
   - `rect` ← `Rect(x, y, w, h)`  
   - `pivot` ← `Vector2(px, py)`  
   - `border` ← kui JSON order is `[left, right, top, bottom]`; note the Unity API
     `Vector4` border order is **(left, bottom, right, top)**, so reorder before writing  
   - `alignment` uses Center (or match the pivot)  
   Save and reimport so the same-named Sprite appears in the Project.

3. **UGUI binding**  
   - Background → `Image` (Simple), covering the safe area or full screen.  
   - Stretchable panel/button base → `Image` + **`Image.Type = Sliced`**, pick a Sprite with non-zero `border`.  
   - Icon → `Image` (Simple), keep the original aspect ratio.  
   - Progress bar → `Image` Filled or Slider background/fill layers.  
   - Sprites with different `state` under the same `component_id`: use `SpriteState` (Button) or script-driven swapping.  
   - `text_policy = no-text`: the image is text-free; overlay `Text`/`TextMeshProUGUI`.

4. **Theme** (optional)  
   Colors / corner radius / font sizes: see `contracts/style-contract.yaml` or `exports/web/tokens.css`; write a ScriptableObject / UGUI theme preset.

5. **Self-check**  
   - Sliced Images keep corners undistorted after stretching.  
   - Sprite `rect` stays in bounds and is not mixed up with other sprites.  
   - Never claim to have generated a SpriteAtlas, Prefab, or `.meta` asset database entries.

## Mapping Reference

| kui field | Unity |
|---|---|
| `texture` | `Texture2D` + Sprite (Multiple) |
| `rect` | `SpriteMetaData.rect` |
| `pivot` | `SpriteMetaData.pivot` |
| `border` | `SpriteMetaData.border` → UI `Image.type = Sliced` |
| `pixelsPerUnit` | `TextureImporter.spritePixelsPerUnit` |
| `component_id` / `state` | Prefab naming / `SpriteState` |

## Reference Demo (demo/)

`demo/` is a **runnable reference implementation** shipped with the exporter: the fixed-template assembler reads `KuiUIData.cs`
(an engine-language mirror of `ui-main.json`) and assembles each screen into a node tree by layout regions,
with every event and screen switch printing one `[kui-demo]` line. Use cases:

- **Smoke test**: run it once to check whether the handoff JSON is self-consistent (region/margins/screen structure);
- **Reference implementation**: when integrating a real project, mirror the demo's assembly approach to reduce guesswork.

See `demo/README.md` for details and verification steps.

## Boundaries

- Does not generate `.unity` scenes, Prefab, SpriteAtlas, or Asmdef.
- Does not write to `ProjectSettings` or create Addressables entries.
- Business logic, networking, and saves are wired up by the game project itself.

```bash
kui export specs/laohuang-battle --force
```
